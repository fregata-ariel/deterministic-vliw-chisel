# Verilator 5.048 の挙動

#98（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.048

スレッドプールは 5.030 と同じ。乱数は 5.046 と同じ。svsim が使う DPI に関わる正しさの修正が入った。

| # | 項目 | 結果 |
|---|---|---|
| A | ビルド | 成功、5 分 50 秒（4 CPU）、コンパイラの警告 3 件（g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0） |
| B | race（`-j 0`） | issue 4931 の abort **0/70000**（abort の出た shard 0/25）、ほかの abort・エラー 0 |
| C | race（`--build-jobs 0 --verilate-jobs 1`） | issue 4931 の abort **0/10000**、ほかの abort・エラー 0 |
| D・G・I | `sbt test`（ADR-0013 の対処あり） | 成功、323 秒。ChiselSim のビルド 53 回。`hw` と `crosscheck`（RTL と参照モデルの差分テスト）を含む |
| E | `sbt test`（対処なし、`-j 0`） | 成功、288 秒; 成功、264 秒 |
| H | `%Warning` | なし |

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.046 から）

- **スレッドプール・終了処理**: 5.046 から変更なし。`attempted to destroy locked Thread Pool` という文字列は、5.030 以降のソースのどこにもない。
- **乱数・seed**: seed の扱いは変更なし（`+verilator+seed+` は 1〜INT_MAX、0 は拒否、seed なしは未初期化の `lrand48()` なので毎回同じ）。seed 1 の出力は 5.046 と同じで、5.020〜5.044 と違う。`$urandom` は、`VlProcess` があるとき（`fork`・timing・`process::srandom` を使う生成関数の中）だけ、プロセスごとの RNG を使う。このプロジェクトの timing のない Chisel の設計には、`VlProcess` はない。
- **正しさの修正**: `V3Life` が、exported DPI 関数が読む変数への代入を消さなくなった（svsim は DPI の import/export でテストベンチと DUT をつなぐ）。wide の条件演算 `VL_COND_WIWW` がマクロになり、選ばれた側だけが評価される。`V3Clean` が `AstNodeSel` を広げない（意図しない整数昇格の修正）。
- **決定性**: スケジューリングの trigger-map の複製が AST の順に並ぶようになった。`V3Delayed`・`V3SplitVar`・`V3Task` のポインタ順の集合が、挿入順の集合に替わった。生成された C++ が、verilation のたびに同じになりやすい。
- **jobs**: 意味は同じ。svsim の `--build-jobs 0` で `--output-groups` が nproc になり、`V3EmitMk` のグループ化が働く（ゼロ除算のガードが入った）。
- **svsim**: C++ API は同じ。多スレッド FST トレース（`--trace-threads`）が削除され、指定すると `DEPRECATED` 警告が出る（`TraceKind.Fst(traceThreads=Some(n))` のときだけ関係する）。`final()` が `executingFinal` を立てるようになり、final ブロックの中でも `$stop` が抑えられない。
- **警告・エラー**: unpacked 配列の代入と pin 接続の互換性の検査が新しいエラーになった。`--structs-packed`・`-f[no-]dfg-pre-inline`・`-f[no-]dfg-post-inline`・`-f[no-]dfg-scoped` は、既定オンの `DEPRECATED` 警告になった（どれも svsim と、このプロジェクトでは使わない）。（実測: 警告なし）
- **ビルド**: configure が jemalloc を先に探し、あれば `verilator_bin` にリンクする（tcmalloc、libc の malloc の順で退く。`--disable-jemalloc` で無効にできる）。このカタログのビルドは tcmalloc も jemalloc も使わない。
- **最適化**: DFG が `V3Scope` の後に1回だけ走る（inline の前後と scoped のパスはなくなった）。`V3LiftExpr` が既定でオン。`--converge-limit` の既定が 100 → 10000。
- **アサーション**: 複数サイクルの SVA の lowering が `V3AssertProp` から新しい NFA エンジン `V3AssertNfa` に替わった。Chisel の assertion が使う即時アサーションに影響しないと見られるが、検証では「証明はされていない」とされた。このプロジェクトの `AssertionSpec` は通っている。
