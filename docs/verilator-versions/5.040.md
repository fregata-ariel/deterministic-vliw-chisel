# Verilator 5.040 の挙動

#94（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.040

スレッドプールは 5.030 と同じ。失敗した assertion が `abort()` でなく `exit(1)` で終わるようになった。DFG の大改修で、同じ入力でも生成された C++ が実行ごとに変わりうる（5.042 で直った）。

## ソースの変更点（前の版 5.038 から）

- **実行時の致命的エラー**: 失敗した assertion、`$stop`、`$fatal`、`$error` が、`std::abort()` でなく `std::exit(1)` で終わる（`debug` レベルが0でないときは abort のまま。`include/verilated.cpp:173-175`）。プロセスは SIGABRT でなく終了コード1で終わる。ChiselSim の assertion のテスト（`AssertionSpec` など）は、この版でも通った。
- **スレッドプール**: 変更なし。`--build` では、C++ のビルドを始める前に verilator_bin がネットリストを解放する。
- **jobs・svsim**: オプションの意味は同じ。`-fno-dfg-break-cycles` と `-fdfg-synthesize-all` が追加された。`verilated.mk` が `-DVERILATOR=1` を常に付ける。
- **乱数・seed**: 変更なし。
- **警告・エラー**: 既定でオンの警告が3つ増えた（`ALWNEVER`、`NOEFFECT`、`SPECIFYIGN`）。svsim は `-Wno-fatal` を渡さないので、出れば verilation が止まる（実測: 警告なし）。IEEE の検査が増えた（`ENUMITEMWIDTH`、`PARAMNODEFAULT`、`PROTOTYPEMIS`、4状態でない型の net、input への代入の `ASSIGNIN`）。
- **DFG の大改修**: 連続代入と小さな always ブロック（基本ブロックと辺が各4以下）が既定で DFG に合成され、組み合わせループの切断が既定でオンになった。生成される C++ が変わる。DFG の合成が、ポインタをキーにした `std::unordered_map` を使うので、同じ入力でも生成された C++ が、ヒープのアドレス（ASLR）次第で変わりうる（5.042 で直った。シミュレーション結果は等価）。
- **正しさの修正**: 非定数の wide（64 ビット超）選択の展開と代入の誤り。ループ展開が、ループ変数の初期代入を残すようになった。
- **その他**: `--skip-identical` が `--cc` で既定オンになり、mtime が変わっても内容の SHA-256 が同じなら verilation を飛ばす。

調査の方法: 調査エージェントの報告 13 件を、別のエージェントが git のオブジェクトを読んで反証しようとした: 確認 13、反証 0、不確実 0。報告の全文（証拠のコード引用つき）と、検証が見落としとして挙げた項目は、[`research/5.040.json`](research/5.040.json) にある。
