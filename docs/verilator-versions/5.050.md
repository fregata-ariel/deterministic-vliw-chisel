# Verilator 5.050 の挙動

#99（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.050

スレッドプールは 5.030 と同じ。既定の seed が 1 になり、`+verilator+seed+0` が毎回ランダムになった。`V3Life` が DPI などをまたいで変数への書き込みを落としうる不具合があり、5.052 で直った（このプロジェクトのテストは通った）。

| # | 項目 | 結果 |
|---|---|---|
| A | ビルド | 成功、6 分 9 秒（4 CPU）、コンパイラの警告 3 件（g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0） |
| B | race（`-j 0`） | issue 4931 の abort **0/70000**（abort の出た shard 0/25）、ほかの abort・エラー 0 |
| C | race（`--build-jobs 0 --verilate-jobs 1`） | issue 4931 の abort **0/10000**、ほかの abort・エラー 0 |
| D・G・I | `sbt test`（ADR-0013 の対処あり） | 成功、337 秒。ChiselSim のビルド 53 回。`hw` と `crosscheck`（RTL と参照モデルの差分テスト）を含む |
| E | `sbt test`（対処なし、`-j 0`） | 成功、314 秒; 成功、286 秒 |
| H | `%Warning` | なし |

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.048 から）

- **seed が替わった**: 既定の seed が、0（「システムの乱数を使う」）でなく **1** になった。`+verilator+seed+0` が受理され、実行ごとにクロックから seed を選ぶ（再現できない）。seed を渡さないときの `$urandom` は毎回同じで、`+verilator+seed+1` と同じ列になる。実測: seed なし＝seed 1＝`b722072d fd8d9d77 24800459 5fa24450`（5.046・5.048 の seed 1 と同じ）、`+verilator+seed+0` は `fe018ed5 9ae7ae20 576938f2 15c39d93`（5.052 では3回とも違う値を確かめた）。`$urandom` の生成経路は 5.048 から変わらない。
- **スレッドプール・終了処理・jobs**: 変更なし。
- **svsim**: 公開 typedef の `WData`・`WDataInP`・`WDataOutP` が `verilated.h` から削除された（`WDataInP`・`WDataOutP` は不透明なハンドルクラスになった）。svsim の `simulation-driver.cpp` は使わない。そのほかの C++ API は同じ。
- **警告・エラー**: `E_CONTASSINIT`（宣言の初期値のある変数、または initial ブロックで書かれる変数への連続代入。抑止できない）、`NOTREDOP`（`!|a` など。抑止できる）、`IEEEMAYDEPRECATE`（手続き的な `assign`/`deassign`。既定オン）。`MULTIDRIVEN` が、always_ff で書かれる変数が別のプロセス（initial を含む）にも書かれる場合も検出する。（実測: 警告なし）
- **実行時のセマンティクス**: initial ブロックの中の `<=` が本物の NBA になった（以前はブロッキング代入として実行され、`INITIALDLY` 警告が出た）。final ブロックの中の `<=` は新しい `FINALDLY` エラー。複数サイクルの並行アサーションで、条件が出続ける `disable iff` が attempt と failure を抑える。入力の組み合わせ領域（ico）の変化検出が既定でオンになった（`-fico-change-detect`）。
- **実行速度**: 実行時の `assertOn()` の判定をまとめ、外側の `if` の外に出す（upstream は、アサーションの多い設計で約10%）。ただし `assertOnGet()` の実装が重くなったので、このプロジェクトでの実行速度の差は、ソースからは予測できず、測る必要がある（検証での訂正）。モジュールのインライン化の見直しと C++ 関数のインライン展開で、upstream は「生成される C++ が減り、実行が10〜20%速くなる」と言う。
- **正しさの問題（5.052 で直った）**: `V3Life` が、DPI や public 関数などの「opaque な呼び出し」を if/else やループの本体の中で見たとき、外側のブロックが覚えている変数の値を無効にしておらず、**変数への書き込みが落ちる、または古い値が転送されうる**（5.052 の `Fix dropping variable writes across opaque calls (#7921)`）。svsim は DPI でテストベンチと DUT をつなぐが、このプロジェクトの `sbt test` は 5.050 でも通った。
- **ビルド**: 同梱の gtkwave の FST ライタ（`fstapi.c`、`lz4.c`、`fastlz`）が、システムの `<lz4.h>`・`<zlib.h>` を使う C++ の `fstcpp` に替わった。FST トレースつきのモデルは `-llz4 -lz` でリンクされる（ubuntu-24.04 では `liblz4-dev` が要る）。`verilator_bin` 自体の要件は増えない。5.048 から、configure が jemalloc（なければ tcmalloc）を `verilator_bin` に自動でリンクする（dev ライブラリがあるとき）。このカタログのビルドは `--disable-tcmalloc --disable-jemalloc` で、どの版も割り当て器を使っていない。
