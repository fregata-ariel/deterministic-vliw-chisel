# Verilator 5.052 の挙動

#100（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.052

スレッドプールは 5.030 と同じ。最新のタグ。生成モデルの eval ループが実行時クラスに移った（小さなモデルでは遅くなる、と upstream は言う）。5.050 の `V3Life` の書き込み落ちが直った。

| # | 項目 | 結果 |
|---|---|---|
| A | ビルド | 成功、5 分 45 秒（4 CPU）、コンパイラの警告 3 件（g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0） |
| B | race（`-j 0`） | issue 4931 の abort **0/70000**（abort の出た shard 0/25）、ほかの abort・エラー 0 |

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.050 から）

- **スレッドプール・終了処理・jobs**: 5.050 から変更なし。複数スレッドのモデル（`--threads`）のスケジューリングの変更（mtask の粗大化、ハザードの修正）は、`-j`・`--verilate-jobs` と無関係。
- **seed**: 5.050 と同じ（既定は 1、`+verilator+seed+0` は毎回ランダム）。`$random(seed)` と分布関数の seed 引数が、write-only でなく read-write として扱われる。乱数による初期化の最適化（変数ごとに1回スレッドコンテキストを読む）は、値を変えない。`VlProcess` の破棄で use-after-free が起きる不具合（`VlRNG::VlRNG()`、#7865）が直った（seed の決め方は変わらない）。実測: seed なし＝seed 1、seed 0 は3回とも違う値。
- **生成コードの構造**: スケジューリングの eval ループが、生成コードから実行時のクラス `VerilatedEvalLoop` に移った。モデルは各 `eval` で全リージョンを仮想呼び出しで実行する（空のリージョンも。upstream は「とても小さなモデルでは遅くなる」と言う）。公開モデル API は、svsim が使う範囲で同じで、`static → initial → settle` の順序も同じ。VPI の記号の登録とスコープの構築が、静的なテーブルを使う形に変わった（生成コード側）。
- **svsim**: `--assert-unroll-limit` が `DEPRECATED`（svsim は渡さない）。新しい実行時の plusarg `+verilator+assert+lock`（RTL の assert 制御文を無視する。既定はオフ）。`DIDNOTCONVERGE` の致命的エラーに、ソースのファイルと行が付かなくなった。
- **警告**: `MULTIDRIVENPROC`・`SIMILARNAME` は style でオフ。`NEVERMATCH` は SVA の `intersect`/`within` が決して合わないときだけ。`MULTIDRIVEN` が clocking block の出力の衝突も検出する。（実測: 警告なし）
- **正しさの修正**: 5.050 の `V3Life` の、opaque な呼び出し（DPI・public 関数など）をまたいだ変数への書き込みが落ちる不具合が直った（`#7921`、上の 5.050 の項を参照）。`V3Gate` が、initial で代入された非定数値を使用箇所にインライン化しなくなった（initial でしか代入されない変数の誤コード）。DFG の peephole が、保護された範囲外の配列読み出し `cond ? arr[i] : x` を、保護のない and/or の式に変えていた（5.050 でのクラッシュまたは不定値）。DFG の `(a<<b)<<c` の畳み込みが、`b+c` を1ビット広く計算する。ネストした選択の指数的な展開（`V3Expand`、#8137）が直った。`$past`、`$rose` などのユーザーが書いたサンプル値関数が、クロックが足りないとき、式の既定のサンプル値を返す。
- **最適化**: DFG が、1つの変数だけを駆動する組み合わせの always ブロックを、制御フローの大きさによらず合成する。複数サイクルの SVA の lowering（NFA）が大きく書き直された（リングバッファの NFA）。
- **ビルド**: 要件は同じ。デバッグ用の実行ファイルは既定で `-O0 -ggdb`（`--enable-light-debug` で `-Og -ggdb1 -gz`）。
- **その他**: `Changes` の `Fix NFA assertion scheduling to fix outcome counts (#7946)` は、リリース前に取り消された古い記載。`VerilatedScope` の構築と破棄が、スレッドローカルの現在のコンテキストでなく、自分のコンテキストを使うようになった（複数のコンテキストをもつプログラムでの破棄の不具合の修正。`VerilatedContext` の破棄は、これまでどおり一時的にスレッドコンテキストを自分に設定する。svsim の単一コンテキストでは影響がない）。
