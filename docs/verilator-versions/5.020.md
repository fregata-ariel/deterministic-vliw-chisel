# Verilator 5.020 の挙動

#86（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 手元のコンテナ（Intel Xeon、4 CPU）での対照

CI の runner は CPU の種類も機械も選べない。同じ機械で版を比べるため、cloud のコンテナ（Intel Xeon @ 2.80GHz、4 CPU、15 GB）で、同じ設計の verilation を `-j 0` で繰り返した。

| 測定 | 回数（`-j 0`） | issue 4931 の abort |
|---|---|---|
| 5.020（ソース） | 7000 | 11 |
| 5.020（ソース、最初の測定） | 3000 | 4 |
| 5.020（apt、最初の測定） | 3000 | 6 |

5.020（ソース）は、2回の測定を合わせて 10000 回に 15 回（0.15%）。

対処（ADR-0013）を外した `sbt test`（`-j 0`）は、手元のコンテナで2回のうち1回失敗した。`WriteReservationsSpec` で `attempted to destroy locked Thread Pool`、`make ... Error 255`（#43 の作業中に見た失敗と同じテスト）。[`local-container/5.020-nofix-failure.txt`](local-container/5.020-nofix-failure.txt)。

## ソースの変更点（この版の仕組み）

- **abort の原因**: `~V3ThreadPool()` は `m_mutex.try_lock()` を1回だけ試し、失敗して実行中のジョブがなければ `attempted to destroy locked Thread Pool` を出して `std::abort()` する（`src/V3ThreadPool.h:142-157`）。プールは関数内の静的な singleton で、`main()` が返った後の静的デストラクタで破棄される。`main()` の最後の `mtDisabler` ブロックが `resumeMultithreading()` で worker を起こし、worker が `m_mutex` を取り直している間に `try_lock` が当たると失敗する（`try_lock` は誤って失敗してもよい、と標準が許している）。`bin/verilator`（Perl）が SIGABRT を `exit 255` にする。
- **この abort は 5.020 で入った**: commit 75a44e5a（`Fix deadlocks in error handler (#4672)`）が、`try_lock` に失敗したときの処理を「`resize(0)` に進む」から abort に変えた。5.018 までは、同じ race が起きても正常に終わっていた。upstream の修正は 5.024（`01dadb0a`）と 5.026（`d1b45b8d`）で入った。
- **`--verilate-jobs 1` で起きない理由**: `Verilator.cpp` が `V3MutexConfig` を `verilateJobs > 1` のときだけ有効にし、1 のときは `V3Mutex::try_lock()` が常に true を返す。`resize(1)` は worker も作らない（`V3ThreadPool.cpp:50-56`）。
- **jobs の意味**: `--build-jobs N`・`--verilate-jobs N` は自分の値だけを決め、0 は `hardware_concurrency()`。`-j N` は、まだ決まっていない方だけを埋める。`make -j` の数は build jobs になる。スレッドプールには verilate jobs の数のスレッド（main＋N-1 の worker）が入る。
- **プールに投げられる仕事**: `V3EmitCImp` の C++ 出力（モジュールごとの slow/fast、トレース）だけ。このため `--verilate-jobs 1` にしても verilation はほとんど遅くならない。
- **seed**: seed がないと `lrand48()` から乱数の状態を作る。`srand48()` はどこでも呼ばれないので、毎回同じ値になる。`+verilator+seed+0` は拒否される（最小は 1）。

調査の方法: 調査エージェントの報告 16 件を、別のエージェントが git のオブジェクトを読んで反証しようとした: 確認 16、反証 0、不確実 0。報告の全文（証拠のコード引用つき）と、検証が見落としとして挙げた項目は、[`research/5.020.json`](research/5.020.json) にある。
