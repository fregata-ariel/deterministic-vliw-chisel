# Verilator 5.026 の挙動

#88（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.026

再試行が最大約1秒（1 ms の sleep つき）に延びた。runner（70000 回）と手元の Intel（10000 回）で abort は観測されなかった。1秒たってもロックが取れなければ abort する経路は、ソースの上では残っている。

| # | 項目 | 結果 |
|---|---|---|
| A | ビルド | 成功、4 分 34 秒（4 CPU）、コンパイラの警告 3 件（g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0） |
| B | race（`-j 0`） | issue 4931 の abort **0/70000**（abort の出た shard 0/25）、ほかの abort・エラー 0 |

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.024 から）

- **スレッドプール**: デストラクタが最初に `m_shutdown = true` を立て、`try_lock` を最大 1000 回、1 ms の sleep を挟んで（最大約 1 秒）繰り返すようになった（`Fix attempted to destroy locked thread pool error (#5040)`）。worker が抜ける時間は十分あるが、1 秒たってもロックが取れなければ abort する経路は、まだ残っている。
- **乱数・seed・jobs**: 5.020 から変更なし。
- **svsim**: `VerilatedContext::addModel` が、シミュレーション時刻が進んだ後に呼ばれると abort する。svsim のドライバーは時刻0でモデルを作るので影響しない。`simulation-driver.cpp` が使う C++ API に削除・改名はない。
- **警告**: 新しい警告 `NONSTD`（既定オン、出すのは `$psprintf` だけ）。幅0（または負）のビット抽出が新しいエラーになった。
- **実行時**: 生成モデルのコンストラクタが `setrlimit(RLIMIT_STACK)` でスタックを予測値の 1.5 倍まで広げようとする。
- **正しさの修正**: 定数畳み込みの減算（`V3Number::opSub` が結果の幅でなく右辺の幅で符号を反転していた）。`mem[a][k +: 8] <= d` のような firtool のマスクつきメモリ書き込みの NBA で、定数の LSB を一時変数なしで使う最適化が入った。
- **ビルド**: configure が SMT ソルバーを任意で探す（なくてよい）。

調査の方法: 調査エージェントの報告 12 件を、別のエージェントが git のオブジェクトを読んで反証しようとした: 確認 12、反証 0、不確実 0。報告の全文（証拠のコード引用つき）と、検証が見落としとして挙げた項目は、[`research/5.026.json`](research/5.026.json) にある。
