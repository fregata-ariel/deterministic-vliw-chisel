# Verilator 5.030 の挙動

#89（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.030

スレッドプールの書き直しで、abort の経路そのものがなくなった。ADR-0013 の対処を外した状態（`-j 0`）でも、全項目で問題がない。

| # | 項目 | 結果 |
|---|---|---|
| A | ビルド | 成功、3 分 36 秒（4 CPU）、コンパイラの警告 3 件（g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0） |
| B | race（`-j 0`） | issue 4931 の abort **0/70000**（abort の出た shard 0/25）、ほかの abort・エラー 0 |
| C | race（`--build-jobs 0 --verilate-jobs 1`） | issue 4931 の abort **0/10000**、ほかの abort・エラー 0 |
| D・G・I | `sbt test`（ADR-0013 の対処あり） | 成功、262 秒。ChiselSim のビルド 53 回。`hw` と `crosscheck`（RTL と参照モデルの差分テスト）を含む |
| E | `sbt test`（対処なし、`-j 0`） | 成功、272 秒; 成功、246 秒 |
| H | `%Warning` | なし |

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.026 から）

- **スレッドプールの書き直し**（commit ffe76717、`Thread pool rewrite (#5161)`）: プールが heap に確保される。デストラクタはロックを取って `m_shutdown = true` にし、`notify_all` して worker を join する。`try_lock` も abort も、`attempted to destroy locked Thread Pool` という文字列も、ソースにない。upstream 4931 の経路は存在しない。コンストラクタは N 個の worker を作る（以前は N-1 個）。N が 1 のときは worker を作らず、ジョブは同期で実行される。worker スレッドで起きたエラーは `::_exit(1)` で終わる（グローバルのデストラクタを飛ばす）。
- **乱数・seed**: 5.020 とバイト単位で同じ実装（行番号の違いを除く）。
- **jobs**: 意味は変わらない。`-j` を引数なしで書いたときの階層ビルドの扱いだけが変わった。
- **アサーション**: 有効/無効の判定が、種別ごと・directive ごとのビットマスク（`assertOnGet`）になった。既定は全ビットが立つので、`--assert` では全部有効のまま。`$fatal` は `+verilator+error+limit` が 1 より大きくても常に止まる。`$sampled` の処理が `V3Sampled` に移った。
- **警告・エラー**: 新しい警告コードはない。`E_LIFETIME` などのエラー系のコードは、`lint_off` や `-Wno` で抑止できなくなった。括弧なしのインスタンス、項目のない `case`、generate-for の外の genvar の参照が、エラーになった。
- **正しさの修正**: `V3Const` の bit-op-tree のマスクの誤コード生成（幅が合わない式）。
- **ビルド**: `make install` の配置が再び入れ替わった（実体が `bin/`、`share/verilator/bin` がスタブ）。テストドライバーが Perl から Python に。
- **実行時**: CPU 時間が常に 0 だった不具合（`clock_gettime` の成功判定の逆転）が直った。

調査の方法: 調査エージェントの報告 23 件を、別のエージェントが git のオブジェクトを読んで反証しようとした: 確認 23、反証 0、不確実 0。報告の全文（証拠のコード引用つき）と、検証が見落としとして挙げた項目は、[`research/5.030.json`](research/5.030.json) にある。
