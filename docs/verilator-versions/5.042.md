# Verilator 5.042 の挙動

#95（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.042

スレッドプールは 5.030 と同じ。シグナルで死んだ `verilator_bin` の終了コードが 255 から 128＋シグナル番号（SIGABRT なら 134）に変わった。5.040 の生成物の非決定性が直った。

| # | 項目 | 結果 |
|---|---|---|
| A | ビルド | 成功、5 分 48 秒（4 CPU）、コンパイラの警告 3 件（g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0） |
| B | race（`-j 0`） | issue 4931 の abort **0/70000**（abort の出た shard 0/25）、ほかの abort・エラー 0 |
| C | race（`--build-jobs 0 --verilate-jobs 1`） | issue 4931 の abort **0/10000**、ほかの abort・エラー 0 |
| D・G・I | `sbt test`（ADR-0013 の対処あり） | 成功、302 秒。ChiselSim のビルド 53 回。`hw` と `crosscheck`（RTL と参照モデルの差分テスト）を含む |

| H | `%Warning` | なし |

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.040 から）

- **終了コード**: `bin/verilator` が、シグナルで死んだ `verilator_bin` を、255 でなく `128 + シグナル番号` で返す（SIGABRT なら 134。`bin/verilator` の「last resort」の行の差分で確認した）。#74 で見た `make: *** [Makefile:12: simulation] Error 255` は、この版以降では `Error 134` になる。
- **終了処理**: 早い終了とエラー終了が `v3Global.vlExit()` を通り、リソース（スレッドプールの破棄と worker の join を含む）を解放してから終わる。スレッドプール・mutex は変更なし。`V3FuncOpt` のマルチスレッドは無効になった（#6440）。
- **jobs**: `-j`・`--build-jobs`・`--verilate-jobs` の 0 が、プロセスの CPU affinity mask の数（`pthread_getaffinity_np`）を意味するようになった。読めないときだけ `hardware_concurrency()` に戻る。実行時の既定のスレッド数にも同じ値が使われる。
- **乱数・seed**: 変更なし。
- **生成物の決定性**: DFG の合成が、ポインタをキーにした map から、変数名で順序づけた `std::map` に変わった。5.040 にあった、生成された C++ が実行ごとに変わりうる問題が直った。
- **最適化**: `--expand-limit` の既定が 64 → 256 ワード（wide 式を語ごとに分ける上限が 2048 → 8192 ビット）。
- **警告・エラー**: `IMPLICITSTATIC` の対象が広がった（always・非 static のタスクで、初期値があり lifetime のない変数）。新しい既定オンの警告: `NORETURN`、`ASSIGNEQEXPR`。既定でエラー: `FUNCTIMECTL`、`HIERPARAM`、モジュールスコープの `automatic` 変数。（実測: 警告なし）
- **トレース**: `--trace-max-width` が、これまで宣言されていただけで効かなかったが、初めて効くようになった（既定 4096、配列の全要素の合計ビット数に適用）。複数のトレース形式を選ぶとエラーになる。
- **svsim**: C++ API は同じ。`verilator` ラッパーが、起動のたびに `verilator_bin --get-supported DEV_ASAN` を余計に実行する。
