# Verilator 5.032 の挙動

#90（親: #85）の結果。方法とチェック項目の定義は [VERILATOR_VERSIONS.md](../VERILATOR_VERSIONS.md#方法) にある。測定は GitHub Actions の `ubuntu-24.04` の runner（`.github/workflows/verilator-catalog.yml`）で行った。第1段は `sbt test` などと race（各構成 10000 回）、第2段は race の `-j 0` だけを 60000 回（20 shards）で、CPU ごとに数えた。

## 5.032

スレッドプールは 5.030 と同じ。Ubuntu 26.04（resolute）の apt の版（5.032-1）。

B の比較の基準は、ソースからビルドした 5.020 の `-j 0`（29/70000、abort の出た shard 6/25）。この版の abort が基準より少ないことの片側 Fisher 検定は、回数の合算で p = 1.9e-09、abort の出た shard の数で p = 0.011。shard（runner）ごとに頻度が大きく違うので、回数を合算した検定は甘くなる。shard の数の検定の方が頑健である。

## ソースの変更点（前の版 5.030 から）

- **スレッドプール・mutex・終了処理**: 5.030 から変更なし。新しい利用者として `V3FuncOpt`（各 CFunc を1つのジョブとして投げる）が入ったが、`--verilate-jobs 1` では worker がなく、同期で実行される。
- **乱数・seed・jobs**: 変更なし。
- **最適化**: `V3FuncOpt` が既定でオン（64 ビット超の左辺への concat の分割と、項が3つを超える concat の平衡化）。`V3Gate` が、`--expand-limit` を超える wide 変数を、複雑な式で駆動されて複数回読まれる場合にインライン化しなくなった。
- **警告**: 新しい警告コードも、既定のオン/オフの変更もない。新しいエラーは、firtool が出さない構文（enum の基底型、event の `wait`、パラメーターへの代入、`--prefix` の値、`--savable` と `--timing`、制約）のものだけ。
- **その他**: 組み込みの lint waiver ファイル（`include/verilated_std_waiver.vlt`、UVM のファイルにだけ効く）を常に読む。`default disable iff` に対応。
- **svsim**: オプションも C++ API も同じ。C++ の最低は C++14 のまま（svsim は `-std=c++17`）。
- **配布**: Ubuntu 26.04（resolute）の apt の版は 5.032-1。

調査の方法: 調査エージェントの報告 11 件を、別のエージェントが git のオブジェクトを読んで反証しようとした: 確認 11、反証 0、不確実 0。報告の全文（証拠のコード引用つき）と、検証が見落としとして挙げた項目は、[`research/5.032.json`](research/5.032.json) にある。
