## ADR-0001: 実装言語をScalaに統一する

- **状態**: 採用（Issue #2）
- **背景**: Phase 0のアセンブラ・encoder・verifier・参照モデルの実装言語を、PythonとScalaから選ぶ必要があった。
- **決定**: Phase 0〜2のソフトウェアも、Phase 1のChisel RTLもScalaで実装する。
- **理由**:
  - machine description、命令表現、トレース形式を、ビルド上の依存関係としてRTL生成器と直接共有できる。
  - ビルド・テスト・CIが1系統（JDK + sbt）で済む。
  - 「別言語なら参照モデルが独立する」という利点は小さい（ADR-0002）。
- **影響**: `compiler/`・`sim/`・`hw/` はすべてsbtのサブプロジェクトになる。Python実装は作らない。

## ADR-0002: 相互検査は言語ではなく状態表現と判定方法の違いで設計する

- **状態**: 採用（Issue #2。具体化は #8, #9, #10）
- **背景**: 参照モデル・verifier・RTLが同じ誤りを共有すると、相互比較しても誤りを検出できない。実装言語を変えても、同じ人が同じ解釈で書けば誤りは共有される。
- **決定**: 独立性は次の3点で確保する。
  1. **状態表現を変える**: 参照モデルはサイクルごとのpending操作キューで値を計算する。verifierは値を持たず、資源予約表とレジスタの書込み中区間で判定する。
  2. **判定方法を変える**: 参照モデルは実行して、実行時の違反（同一境界の二重書込みなど）を検出する。verifierは命令列だけから静的に合法性を判定する。
  3. **期待値を手で作る**: ISA.mdの命令例のように、commit時刻・最終状態・cycles・拒否理由を人が書いたテストケースを基準にする。モデルの出力をそのままgoldenとして採用する前に、手作りの期待値と照合する。
- **ビルド上の強制**: `compiler`（verifierを含む）と `sim` は `isa` にのみ依存し、互いに依存しない（`build.sbt`）。両者を突き合わせるテストは、#10 で別のテストプロジェクトに置く。
- **影響**: 実行意味論は #5 で文書として先に確定し、各実装はその文書から独立に導く。

## ADR-0003: Lean 4は仕様確定後に小さな対象へ限定して導入を検討する

- **状態**: 採用（導入の判断は保留）
- **背景**: 形式検証は決定論性の主張と相性が良い。一方で、仕様が動いている段階で組み込むと重い。また、証明を書かない場合のLean 4は普通の関数型言語であり、書き手が少ないため開発支援（AIエージェントを含む）の精度も下がる。
- **決定**: Phase 0〜1では導入しない。ISAと実行意味論が安定した後、小さな検証対象に限定して導入を検討する。
- **候補**: encoder/decoderの全単射性。MVPの合法性規則の下で、実行サイクル数が入力値に依存しないこと。verifierの規則が意味論上の違反をすべて含むこと。

## ADR-0004: ツールチェーンとバージョン固定

- **状態**: 採用（Issue #2）
- **方針**:
  - バージョンはすべて固定する。採用するのはリリースから2週間以上経った版だけにする。
  - 更新はPRで行い、この表と `build.sbt`・`project/` を同時に変える。
  - Scalaのバージョンは、Phase 1で使うChiselが要求する版に合わせる。

| 対象 | バージョン | 固定場所 | 備考 |
|---|---|---|---|
| JDK | 21 | `.github/workflows/ci.yml` | CIはTemurin |
| Scala | 2.13.18 | `build.sbt` | Chisel 7.16.0 のPOMが要求する版 |
| sbt | 1.12.15 | `project/build.properties` | sbt 2.x はプラグインとChiselの追随を待つ |
| ScalaTest | 3.2.20 | `build.sbt` | ChiselSimと同じテスト基盤 |
| scalafmt | 3.11.5 | `.scalafmt.conf` | |
| sbt-scalafmt | 2.6.2 | `project/plugins.sbt` | |
| Chisel | 7.x（Phase 1で固定） | — | 2026-10-14時点の最新は7.16.0（2026-10-01公開）。Phase 1着手時に、2週間以上経った版から選ぶ |

- **コンパイラ設定**: `-deprecation -feature -unchecked -Xlint -Werror`。警告はすべてエラーとして扱う。
- **sbtプロジェクト構成**:

| プロジェクト | ディレクトリ | 依存 | 内容 |
|---|---|---|---|
| `isa` | `isa/` | — | machine description、命令表現、エンコーディング |
| `compiler` | `compiler/` | `isa` | アセンブラ、verifier、Phase 2のスケジューラ |
| `sim` | `sim/` | `isa` | サイクル精度の参照モデル |
| `hw` | `hw/` | `isa`（予定） | Phase 1で追加するChisel RTL |

## ADR-0005: CIの入口と起動条件

- **状態**: 採用（Issue #3）
- **決定**:
  - 手元とCIの入口を `scripts/check.sh` に一本化する。CIのジョブはこのスクリプトを呼ぶだけにする。
    - `static`: JSON構文、shellcheck、追跡ファイルの空白エラー
    - `scala`: `sbt scalafmtSbtCheck scalafmtCheckAll test`
  - 起動条件は、`main` へのpush、すべてのPR、手動実行とする。作業ブランチではPRを開いてCIを回す。（当初は全ブランチへのpushで起動し、PRでは二重実行を避けてジョブを`if`で飛ばしていたが、PR上に同名のskippedチェックが並び紛らわしいため変更した。）
  - `permissions: contents: read` にする。`main` 以外では、同じrefの古い実行をキャンセルする。
  - 使用するActionは、公式（`actions/*`）とsbt公式（`sbt/setup-sbt`）のメジャータグで固定する。第三者のActionを追加する場合はcommit SHAで固定する。
- **今後**: Phase 1でChisel・firtool・Verilatorのジョブを追加する。golden traceの比較は #8 以降で `scala` ジョブのテストとして追加する。
